# 接口设计

## 1. 通用约定

- 后端地址：`http://localhost:8080`；用户侧通过 Vite 代理 `/api` → 后端，实际路径去掉 `/api`；
- 用户侧接口前缀：`/portal`；
- 认证：除登录外均需 `Authorization: Bearer <token>`；token 由 RuoYi `SysLoginService` 签发，默认 30 分钟；
- 响应统一为 RuoYi `AjaxResult`：`{ "code": 200, "msg": "操作成功", "data": ... }`；
- 失败：`code=500` + 中文 `msg`；未登录/过期：`code=401`；
- 日期字段统一返回 `yyyy-MM-dd HH:mm:ss` 字符串；
- 分页：管理端由 RuoYi `startPage()` + `TableDataInfo` 处理；用户端数据量小，列表一次返回，前端客户端分页。

## 2. 用户侧接口

### 2.1 登录与身份

| 方法 | 路径 | 请求 | 返回 data |
|---|---|---|---|
| POST | `/portal/auth/login` | `{username,password}` | `{token,user:{loginId,role,name,classId,className,manageClassIds}}` |
| GET | `/portal/auth/profile` | — | 同上 `user` |

说明：登录先确认 user_name 在 `edu_student` 或 `edu_teacher` 中存在，再调用 RuoYi `SysLoginService.login` 校验密码并签发 JWT。admin 账号不属于门户身份，会被拒绝。

### 2.2 下拉选项

| 方法 | 路径 | 返回 data |
|---|---|---|
| GET | `/portal/options` | `{terms:[],classes:[{classId,className}],courses:[{courseId,courseName,credit,term,teacherId,courseType}]}` |

学生只返回本人班级；教师返回所带班级。

### 2.3 成绩

| 方法 | 路径 | 参数 / 请求体 | 说明 |
|---|---|---|---|
| GET | `/portal/scores` | `term,keyword,classId,courseId`（可选） | 学生查本人；教师查所带班级；返回成绩 VO 数组 |
| GET | `/portal/scores/roster` | `classId,courseId,term` | 教师批量录入名单（含已录入标记） |
| GET | `/portal/scores/{scoreId}/logs` | — | 修改记录 |
| POST | `/portal/scores/batch` | `{classId,courseId,term,rows:[{studentId,usualScore,finalScore}]}` | 教师批量录入/更新，返回 `{savedCount}` |
| PUT | `/portal/scores/{scoreId}` | `{usualScore,finalScore,reason}` | 教师单条修改，写入修改记录 |

成绩 VO 字段：

```
scoreId, studentId, studentName, classId, className,
courseId, courseName, credit, courseType, term,
usualScore, finalScore, totalScore, gpa, status,
recorderId, recordTime
```

`status` 取值 `NORMAL / APPEALING / MODIFIED`，由 SQL 根据 PENDING 申请与修改记录推导。

### 2.4 查分申请

| 方法 | 路径 | 参数 / 请求体 | 说明 |
|---|---|---|---|
| POST | `/portal/appeals` | `{courseId,reason}` | 学生提交；理由 10~200 字；同课程不能重复 PENDING |
| GET | `/portal/appeals/mine` | — | 学生本人申请 |
| GET | `/portal/appeals` | `status=PENDING\|HANDLED,keyword,courseId` | 教师待办/已办 |
| PUT | `/portal/appeals/{appealId}/handle` | `{result:KEEP\|CORRECT,correctedScore,opinion}` | 受理；CORRECT 需 0~100 更正分 |
| PUT | `/portal/appeals/{appealId}/reject` | `{opinion}` | 驳回 |

申请 VO 在申请字段之外还带 `studentName/className/courseName/credit/usualScore/finalScore/handlerName`，供列表直接展示。

### 2.5 AI 咨询

| 方法 | 路径 | 请求 | 返回 data |
|---|---|---|---|
| GET | `/portal/ai/status` | — | `{enabled, model}` |
| POST | `/portal/ai/chat` | `{messages:[{role,content}]}` | `{reply, model, usage:{promptTokens,completionTokens,totalTokens}}` |

说明：

- API Key 只保存在后端 `deepseek.api-key`（优先读环境变量 `DEEPSEEK_API_KEY`），**不会下发到浏览器**；
- 后端把对话转发到 `https://api.deepseek.com/chat/completions`，默认模型 `deepseek-chat`；
- 只接受 `system/user/assistant` 三种角色，单条最长 4000 字，最多保留最近 20 条；
- 网络偶发失败自动重试（最多 3 次），401/402/400 不重试，直接返回原因；
- 未配置 Key 时返回 `code=500` 与友好提示，前端在对话栏顶部展示。

## 3. 管理端接口（代码生成）

生成模块统一为 RuoYi CRUD 风格：

| 模块 | 列表 | 详情 | 新增 | 修改 | 删除 |
|---|---|---|---|---|---|
| 成绩 | `GET /system/score/list` | `GET /system/score/{id}` | `POST /system/score` | `PUT /system/score` | `DELETE /system/score/{ids}` |
| 查分申请 | `/system/appeal` | 同上 | 同上 | 同上 | 同上 |
| 课程 | `/system/course` | 同上 | 同上 | 同上 | 同上 |
| 学生 | `/system/student` | 同上 | 同上 | 同上 | 同上 |
| 教师 | `/system/teacher` | 同上 | 同上 | 同上 | 同上 |
| 班级 | `/system/classroom` | 同上 | 同上 | 同上 | 同上 |

- 权限标识：`system:<businessName>:list/query/add/edit/remove/export`；
- 菜单挂在 `成绩管理` 目录（menu_id 2000）下；
- 管理端成绩新增/修改时，`ScoreServiceImpl` 会重新计算总评/绩点，并设置录入人/时间；
- 文件位置：Controller 在 `ruoyi-system/.../controller`，Domain/Mapper/Service 在 `ruoyi-system`，Vue2 页面在 `ruoyi-ui/src/views/system/<business>`。

## 4. 错误码与异常

| 场景 | code | 示例 msg |
|---|---|---|
| 成功 | 200 | 操作成功 |
| 参数/业务校验失败 | 500 | 该课程已有待受理的查分申请，请勿重复提交 |
| 无权访问 | 403 | 没有权限，请联系管理员授权 |
| 未登录/过期 | 401 | 认证失败，无法访问系统资源 |
| 系统异常 | 500 | 系统异常，请联系管理员 |

前端 `src/api/request.js` 统一处理：`code !== 200` 抛出 `Error(msg)`；`code=401` 清除 token 并跳转登录页。
