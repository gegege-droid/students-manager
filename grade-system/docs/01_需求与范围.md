# 成绩管理系统 —— 需求与范围

> 本文件是实验三用户侧应用的需求依据，内容来自实验一 `students-manager/docs/01-requirements.md`，并按实验三的实际实现范围做了收敛。

## 1. 项目目标

面向高中成绩管理场景，提供两类用户：

- **学生**：登录后查看本人成绩、统计信息；对成绩有疑问时在线提交查分申请，并查看受理进度。
- **班主任（教师）**：按班级/课程批量录入成绩；修改成绩时必须填写原因并留痕；在待办列表中受理查分申请，可维持原成绩或更正成绩。

系统同时提供 **RuoYi 管理端** 作为后台维护入口（用户、角色、菜单、成绩、查分申请、课程、学生、教师、班级）。

| 查看本人查分申请 | ✅ | — | — |
| 受理/驳回查分申请 | — | ✅（所带班级） | 全部（维护） |

| 修改成绩并留痕 | — | ✅（所带班级） | 全部 |
| 代码生成模块 CRUD | — | — | ✅ |

关键约束：

1. 学生只能访问自己的成绩和申请；
2. 教师只能操作自己所带班级（`edu_classroom.head_teacher_id = 教师工号`）；
3. 存在 PENDING 查分申请的成绩状态为 `APPEALING`，禁止教师直接修改；
4. 同一学生、课程、学期只能有一条成绩，且不能重复提交 PENDING 申请；
5. 修改成绩必须记录原值、新值、原因、操作人、时间；查分受理更正也必须留痕。

## 4. 核心业务规则

### 4.1 成绩计算

- 总评 = `round(平时 × 0.4 + 期末 × 0.6)`，任一项为空则总评为空；
- 绩点 = `总评 < 60 ? 0 : (总评 − 50) / 10`，保留 1 位小数；
- 平均分 = 总评算术平均，保留 1 位小数；
- 平均绩点 = `Σ(绩点 × 学分) / Σ学分`，保留 2 位小数。

### 4.2 成绩状态

| 状态 | 触发条件 |
|---|---|
| `NORMAL` | 首次录入后默认状态 |
| `APPEALING` | 存在该学生+课程+学期的 PENDING 查分申请 |
| `MODIFIED` | 存在该学生+课程的成绩修改记录（手工或查分更正） |

状态由后端 SQL 推导，不单独存储，避免状态与数据不一致。

### 4.3 查分申请状态机

```
PENDING ──受理(KEEP)────► ACCEPTED
   │    ──受理(CORRECT)─► ACCEPTED
   └──驳回──────────────► REJECTED
```

- `PENDING`：学生提交后的初始状态，教师待办 +1；
- `ACCEPTED`：填写 5~200 字处理意见；`CORRECT` 必须填写 0~100 更正分；
- `REJECTED`：必须填写 5~200 字驳回理由；
- `ACCEPTED/REJECTED` 为终态，不能重复受理。

### 4.4 校验规则

| 字段 | 规则 |
|---|---|
| 账号 | 4~12 位字母/数字（学号 7 位、工号 T001 为 4 位） |
| 密码 | 6~20 位 |
| 成绩 | 0~100 整数 |
| 申请理由 | 10~200 字 |
| 修改原因 | 5~100 字 |
| 处理意见/驳回理由 | 5~200 字 |
| 更正成绩 | 选择 CORRECT 时必填，0~100 整数 |

## 5. 范围边界

本期做：

- 用户端 7 个页面（含个人中心）的真实前后端闭环；
- 管理端 6 个代码生成 CRUD 模块；
- 成绩、查分、修改记录的核心业务规则；
- 详细设计文档与测试说明。

本期不做：

- 注册、找回密码、第三方登录；
- 短信/站内通知；
- 附件上传、电子签章；
- 多级审批流；
- 移动端适配。
