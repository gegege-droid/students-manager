# 数据库设计

## 1. 设计原则

- 数据库：MySQL 5.7，统一 `InnoDB + utf8mb4`；
- 业务表统一 `edu_` 前缀，便于 ruoyi-generator 用 `autoRemovePre + tablePrefix=edu_` 去掉前缀；
- **不建物理外键**：便于代码生成 CRUD、演示数据重置和批量导入，引用完整性由 Service 层保证；
- 主键使用业务编号（学号、课程号、成绩编号、申请编号），便于与前端/演示数据对应；
- 所有表保留 RuoYi 审计字段：`create_by/create_time/update_by/update_time/remark`；
- 状态字段只存 `PENDING/ACCEPTED/REJECTED` 等原始状态；成绩的 `NORMAL/APPEALING/MODIFIED` 由 SQL 根据查分与修改记录推导。

## 2. 表清单与关系

```
edu_classroom 1 ─── n edu_student
edu_teacher   1 ─── n edu_classroom (head_teacher_id)
edu_teacher   1 ─── n edu_course    (teacher_id)
edu_student   1 ─── n edu_score
edu_course    1 ─── n edu_score
edu_student   1 ─── n edu_appeal
edu_course    1 ─── n edu_appeal
edu_score     1 ─── n edu_score_change_log
```

| 表 | 说明 | 主键 | 关键约束 |
|---|---|---|---|
| `edu_classroom` | 班级 | `class_id` | `class_name` 唯一 |
| `edu_student` | 学生 | `student_id` | `class_id` 索引 |
| `edu_teacher` | 教师 | `teacher_id` | — |
| `edu_course` | 课程 | `course_id` | `(course_name, term)` 唯一；`teacher_id` 索引 |
| `edu_score` | 成绩 | `score_id` | `(student_id, course_id, term)` 唯一 |
| `edu_appeal` | 查分申请 | `appeal_id` | `(status, apply_time)` 索引 |
| `edu_score_change_log` | 成绩修改记录 | `log_id` | `score_id`、`(student_id, course_id)` 索引 |

完整 DDL 见 `db/01_schema_grade.sql`。

## 3. 关键字段说明

### 3.1 edu_score

| 字段 | 类型 | 说明 |
|---|---|---|
| score_id | varchar(32) | 成绩编号，如 `SC20250101001` |
| student_id / course_id / term | varchar | 学生、课程、学期 |
| usual_score / final_score | int | 平时/期末，0~100，可为空 |
| total_score | int | 总评，由 40%+60% 计算 |
| gpa | decimal(3,1) | 绩点 |
| manual_total | char(1) | 总评是否被查分更正（0/1） |
| recorder_id / record_time | varchar/datetime | 录入人、录入时间 |

唯一键 `uk_score_stu_course_term` 防止同一学生同一课程同一学期重复录入。

### 3.2 edu_appeal

| 字段 | 说明 |
|---|---|
| appeal_id | `AP + yyyyMMdd + 3 位序号` |
| original_score | 申请时的总评快照，之后不随成绩修改变化 |
| reason | 10~200 字 |
| status | PENDING / ACCEPTED / REJECTED |
| result | KEEP / CORRECT |
| corrected_score | 更正后总评，仅 CORRECT 有值 |
| opinion | 处理意见/驳回理由，5~200 字 |
| handler_id / handle_time | 受理人、受理时间 |

### 3.3 edu_score_change_log

保存每次手工修改或查分更正的原值、新值、原因、操作人、时间、来源（MANUAL/APPEAL），是成绩留痕和状态推导的依据。

## 4. 索引设计

- `edu_score`：唯一键 `(student_id, course_id, term)` 同时覆盖学生查分与防重；`(course_id, term)`、`(student_id, term)` 支撑教师按课程/学期筛选；
- `edu_appeal`：`(status, apply_time)` 支撑待办列表；
- `edu_score_change_log`：`score_id` 支撑按成绩查历史，`(student_id, course_id)` 支撑状态推导。

## 5. 种子数据

`db/02_seed_grade.sql` 维护系统使用的演示数据，源自实验一的[原型数据字典](../../docs/04-data-and-vue.md)。

- 1 个班级 G2101（高一(1)班），班主任 T001；
- 6 名学生 2021001~2021006；
- 9 门课程 CHN101~GEO101，学期 `2024-2025-1`；
- 12 条成绩（张三 9 条、王五 2 条、钱七 1 条）；
- 5 条查分申请（3 条 PENDING、1 条 ACCEPTED、1 条 REJECTED）；
- 2 条修改记录（MANUAL / APPEAL）。

演示数据的预期效果：

- 张三 HIS101 状态 `APPEALING`（有 PENDING 申请）；
- 张三 CHN101、PHY101 状态 `MODIFIED`（有修改记录）；
- 教师待受理 3 条、已处理 2 条。

## 6. 账号与菜单

- `db/03_portal_accounts.sql`：在 `sys_user/sys_role/sys_user_role` 中创建学生/教师门户账号，并关闭验证码；
- `db/04_menu_grade.sql`：创建「成绩管理」父菜单（2000）及 6 个生成模块菜单/按钮；
- 管理端 admin 使用 RuoYi 内置 `admin/admin123`。

## 7. 重置与迁移

- 重置演示数据：执行 `db/02_seed_grade.sql`；
- 全量初始化：执行 `db/00_grade_system_all.sql`；
- 修改表结构后：在代码生成页面「同步」表结构，或在 gen 表中删除后重新导入。
