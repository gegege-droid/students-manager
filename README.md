## 二、六个页面一览

| 编号 | 页面 | 角色 | 核心功能 | 关联需求 |
|---|---|---|---|---|
| P1 | 学生登录 | 公共 | 账号 + 密码 + 验证码，按角色分流到不同首页 | FR-P1-01~07 |
| P2 | 成绩查询 | 学生 | 学期/课程筛选、成绩列表、统计汇总、分数着色、跳转申请查分 | FR-P2-01~10 |
| P3 | 申请查分 | 学生 | 选课程带出原成绩、填理由、提交、查看申请进度 | FR-P3-01~09 |
| P4 | 添加学生成绩 | 班主任 | 选班级课程批量录入、总评自动计算、进度提示 | FR-P4-01~09 |
| P5 | 修改学生成绩 | 班主任 | 查询定位、原值/新值对照、原因必填、二次确认、修改记录留痕 | FR-P5-01~08 |
| P6 | 受理查分申请 | 班主任 | 待办列表、受理弹窗、维持/更正成绩、处理意见、状态流转 | FR-P6-01~10 |

**业务闭环（答辩演示主线）**

```
学生登录 → 查成绩 → 对不及格课程申请查分
    → 班主任登录 → 受理该申请（更正成绩 + 处理意见）
    → 成绩修改记录留痕 → 学生查看处理结果
```

## 三、快速上手

### 1. 看线框图

双击 `wireframes.html`，用 Chrome / Edge 打开。顶部有跳转导航，可逐页查看。

### 2. 用 Axure 做原型

1. 新建工程，页面样式统一 `1440 × 900`，按 `02-axure-guide.md` §1.2 建页面树。
2. 按 §2 定颜色与字号，按 §3 做 6 个母版（这是最省时间的一步）。
3. 按 `03-wireframe-spec.md` 逐页搭，每页照着「布局结构 → 区域说明 → 字段校验 → 交互清单」四张表填。
4. 按 §7 给元件写注释（带 FR 编号），这样导出说明文档时需求自动可追溯。
5. 按 §8 发布为 HTML，打包 `grade-system.rp` + `prototypes/` 提交。

### 3.（已生成）前端页面

`grade-front/` 就是按 `04-data-and-vue.md` §4 落地的 Vue 3 + Vite 工程，6 个页面全部实现。本机环境已验证（Node v24.18.0 / npm 11.16.0），依赖已安装、构建已通过。

```bash
cd grade-front
npm run dev        # 开发模式，自动打开 http://localhost:5173
npm run build      # 构建到 dist/
npm run preview    # 预览构建产物（http://localhost:4173）
```

测试账号：学生 `2021001` / `123456`，班主任 `T001` / `123456`。登录页底部有「重置演示数据」。

> ⚠️ `dist/index.html` **不能**直接双击用 `file://` 打开（浏览器 CORS 策略会拒绝加载 ES Module），请用 `npm run dev` 或 `npm run preview`。

演示路径、页面路由表、实现要点见 `grade-front/README.md`。

## 四、需要你确认的地方

作业原文提到「成绩管理系统文字需求见**下页 PPT**」，但该 PPT 未提供，因此需求是按同类高校成绩管理系统的通行做法**自拟**的。

所有自拟项已在 `01-requirements.md` §6「假设与待确认项」逐条列出，主要包括：

| 假设 | 影响范围 |
|---|---|
| 角色只有「学生」和「班主任」 | 权限矩阵、菜单 |
| 总评 = 平时 40% + 期末 60% | P2/P4/P5 的计算列 |
| 绩点 = (总评 − 50) / 10，60 分以下为 0 | P2 列表 |
| 查分结果只有「维持原成绩 / 更正成绩」 | P6 弹窗 |
| 成绩状态含「查分中」，此时禁止改分 | P5 锁定逻辑 |
| 只做 PC 端 Web，不做移动端 | 页面尺寸 |

**拿到 PPT 后**，只需修改 `01-requirements.md` 的 §4 功能需求表和 §6 假设表，页面结构无需重做。

## 六、关键设计亮点（答辩时可以重点讲）

1. **有完整的业务闭环**，不是 6 个孤立的页面：学生申请 → 教师受理 → 成绩更正 → 修改留痕 → 学生查看结果。
2. **成绩修改强制留痕**：原成绩不可删除，每次修改记录操作人、时间、原因（P5）。
3. **流程状态约束**：成绩处于「查分中」时禁止直接改分，必须先走完受理流程（P5 锁定提示）。
4. **校验与错误处理完整**：每个字段都有明确的校验时机与错误文案，颜色不是唯一信息载体（低分同时有「不及格」文字标签）。
5. **一致性设计**：统一母版、统一四段式布局、统一空状态与反馈，14 项一致性检查清单可逐条验收。
6. **需求可追溯**：每个元件注释带 FR 编号，可导出 Axure 说明文档形成需求追踪矩阵。
