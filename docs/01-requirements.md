## 1. 项目背景与目标

### 1.1 背景

高校每学期末的成绩相关工作集中在两类人身上：

- **学生**：只能被动等待成绩公布，对成绩有疑问时靠线下找老师、发消息，缺少正式的查分渠道，且**无法追踪自己的申请进展**。
- **班主任（任课教师）**：成绩录入靠 Excel 汇总再统一报送，**录入与修改都没有留痕**；学生查分申请通过口头或聊天软件受理，**容易漏办、无法统计**。

### 1.2 目标

做一套 Web 端成绩管理系统原型，达成三件事：

1. **学生侧自助**：登录 → 查成绩 → 对有疑问的课程在线提交查分申请 → 查看受理进度。
2. **教师侧规范**：登录 → 录入成绩 → 修改成绩（必须填写修改原因，留痕）→ 在待办列表中受理查分申请并给出处理意见。
3. **流程可追溯**：每一次成绩变更和每一次查分受理，都有操作人、操作时间和原因。

### 1.3 原型范围（做什么 / 不做什么）

| 范围内（本次原型要做） | 范围外（本次原型不做，可在文档中说明为「后续扩展」） |
|---|---|
| 学生 / 班主任两种角色的登录 | 注册、找回密码、第三方登录 |
| 成绩查询（筛选 + 列表 + 统计） | 成绩单导出 PDF、打印 |
| 查分申请提交与进度查看 | 站内消息 / 短信通知 |
| 成绩录入、修改（含修改原因留痕） | 成绩审核多级审批流 |
| 查分申请受理（通过 / 驳回 + 回复） | 附件上传的防篡改、电子签章 |
| 6 个页面的界面与交互 | 真实数据库、真实接口、权限后端校验 |

> 原型是**界面与交互的说明工具**，所以「不做」不是缺陷，而是要在需求规格说明书里明确写清边界，这恰恰是评分点。

## 2. 角色与权限

### 2.1 角色定义

| 角色 | 标识 | 说明 | 登录凭证 |
|---|---|---|---|
| 学生 | `STUDENT` | 在校学生，只能看自己的成绩 | 学号 + 密码 |
| 班主任 | `TEACHER` | 兼班主任与任课教师，管理所带班级 | 工号 + 密码 |

> 本原型不设第三个「系统管理员」角色，页面数已满足作业要求；如需展示权限差异，用两个角色的菜单不同来体现即可。

### 2.2 权限矩阵

| 功能 | 学生 | 班主任 | 对应页面 |
|---|:---:|:---:|---|
| 登录系统 | ✅ | ✅ | P1 |
| 查询本人 / 本班成绩 | ✅ 仅本人 | ✅ 仅所带班级 | P2 |
| 查看成绩统计（平均分、学分绩点） | ✅ | ✅ 班级维度 | P2 |
| 提交查分申请 | ✅ | ❌ | P3 |
| 查看查分申请进度 | ✅ 仅本人 | ✅ 全部待办 | P3 / P6 |
| 录入学生成绩 | ❌ | ✅ | P4 |
| 修改学生成绩 | ❌ | ✅ | P5 |
| 受理查分申请（通过 / 驳回） | ❌ | ✅ | P6 |

**关键约束（务必在说明书里写明）**

1. 学生只能查询和申请**自己的**成绩，不能看到他人成绩。
2. 班主任只能操作**自己所带班级**的学生成绩。
3. 成绩一旦被修改，原成绩**不能删除**，必须生成一条修改记录（谁改的、什么时候、为什么改）。
4. 已进入「查分受理中」状态的成绩，班主任不能直接修改，必须先完成受理流程。

## 5. 业务规则

### 5.1 状态机 —— 查分申请

```
                    ┌──────────────────────────────┐
                    │                              │
  学生提交           │  班主任受理                   │ 班主任驳回
  ────────►  待受理 ─┴──► 已受理（维持原成绩）        │
                │        │                          │
                │        └► 已受理（更正成绩）       │
                └───────────────────────────────────► 已驳回
```

| 状态值 | 中文 | 谁能改 | 说明 |
|---|---|---|---|
| `PENDING` | 待受理 | 学生可撤回（扩展） | 初始状态，班主任待办数 +1 |
| `ACCEPTED` | 已受理 | — | 终态，处理意见写入 `result`，若更正成绩则同步更新成绩表 |
| `REJECTED` | 已驳回 | — | 终态，必须填写驳回理由 |

### 5.2 状态机 —— 成绩记录

| 状态值 | 中文 | 触发条件 |
|---|---|---|
| `NORMAL` | 正常 | 首次录入后的默认状态 |
| `APPEALING` | 查分中 | 学生对该课程提交了查分申请且处于 `PENDING`，此时**禁止班主任直接修改** |
| `MODIFIED` | 已修改 | 班主任修改过该成绩（或查分受理结果为更正），保留修改记录 |

### 5.3 成绩计算公式

| 指标 | 公式 | 说明 |
|---|---|---|
| 平时成绩 | 手工录入，0~100 整数 | 占比 40% |
| 期末成绩 | 手工录入，0~100 整数 | 占比 60% |
| 总评成绩 | `round(平时 × 0.4 + 期末 × 0.6)` | 全学期统一，不允许教师自行调整比例 |
| 绩点 | `总评 < 60 ? 0 : (总评 - 50) / 10` | 保留 1 位小数，60 分对应 1.0 |
| 平均分 | 所有课程总评的算术平均 | 保留 1 位小数 |
| 平均绩点 | `Σ(绩点 × 学分) / Σ学分`（学分绩点） | 保留 2 位小数 |

> 权重 0.4 / 0.6 是**自拟假设**，见 §6。若 PPT 另有规定，只改这一张表。

### 5.4 校验规则汇总

| 字段 | 规则 | 错误提示文案 |
|---|---|---|
| 账号 | 必填，6~12 位数字或字母 | 请输入学号或工号 |
| 密码 | 必填，6~20 位 | 请输入密码 |
| 验证码 | 必填，4 位 | 请输入验证码 |
| 成绩分数 | 必填，0~100 的整数 | 成绩必须是 0~100 的整数 |
| 申请理由 | 必填，10~200 字 | 请填写 10~200 字的申请理由 |
| 修改原因 | 必填，5~100 字 | 请填写修改原因（5~100 字） |
| 处理意见 | 必填，5~200 字 | 请填写处理意见 |
| 更正后成绩 | 选择「更正成绩」时必填，0~100 整数 | 请填写更正后的成绩 |

## 7. 非功能需求（原型阶段的要求，用于说明书正文）

| 类别 | 要求 |
|---|---|
| 界面尺寸 | PC 端 1440×900，主流笔记本 1366×768 下不出现横向滚动条 |
| 视觉风格 | 主色 `#2B6CB0`（蓝），辅色 `#38A169`（成功）/ `#E53E3E`（错误）/ `#ED8936`（警告）；正文 14px，标题 16~20px |

| 响应时间 | 原型阶段仅标注预期：页面加载 < 2s，查询 < 1s |
