# 六个页面的线框设计说明

> 本文是**逐页施工图**：每个页面的区域划分、元件清单、字段校验、交互行为、状态设计。
> 在 Axure 里搭页面时，**左边开着这份文档，右边开着 Axure**，照着填即可。
>
> 配套：`wireframes.html` 是同内容的灰度线框视觉图（浏览器打开、可打印成 PDF 截图贴进说明书）。

---

## 0. 线框约定

### 0.1 画布与栅格

| 项目 | 规格 |
|---|---|
| 页面尺寸 | **1440 × 900**（全部 6 页统一） |
| 栅格 | 12 列，列宽 96，槽宽 24，页面左右外边距 24 |
| 顶部导航 | 高 **64**，固定顶部，全宽 |
| 侧边菜单 | 宽 **240**，从 y=64 开始，高度撑满 |
| 内容区 | x=240，y=64，宽 1200，高 836，内部左右各留 24 内边距 → 可用宽 **1152** |
| 卡片间距 | 16 |
| 卡片圆角 | 8，边框 `#E2E8F0`，无阴影或极轻阴影 |
| 左下角页脚 | 高 40，仅在内容区最底部 |

### 0.2 公共框架（所有登录后页面共用）

**一致性规则（跨 6 页必须成立）**

| 规则 | 说明 |
|---|---|
| 卡片 | 所有内容块放在白色卡片内，页面底色 `#F7FAFC` |
| 按钮顺序 | 主按钮在右、次按钮在左，主按钮宽 ≥ 88，高 36 |
| 表格 | 表头背景 `#EDF2F7`，行高 44，表头文字 14px 次要色，隔行 `#F7FAFC` |
| 必填标记 | 字段名后加红色 `*` |
| 错误提示 | 统一放在**对应输入框正下方**，12px，`#E53E3E` |
| 空状态 | 居中：图标 + 一行主文案（16px）+ 一行辅助文案（12px 次要色） |
| 返回/取消 | 表单类页面的次要按钮统一叫「重置」或「取消」 |

|---|---|:---:|:---:|---|---|

| 密码 | `ipt_密码` | 文本框（密文） | ✅ | 6~20 位 | 请输入密码 |
| 验证码 | `ipt_验证码` | 文本框 | ✅ | 4 位，不区分大小写 | 请输入验证码 |
| 记住账号 | `cb_记住账号` | 复选框 | ❌ | — | — |

**匹配规则（原型用，来自 §6 假设）**

| 账号 | 密码 | 角色 | 跳转 |
|---|---|---|---|
| `2021001` | `123456` | 学生 | P2 成绩查询 |
| `T001` | `123456` | 班主任 | P6 受理查分申请 |
| 其他 | 任意 | — | 显示 `dp_登录错误` |

> 【要点】这两个账号要写在**登录页的元件注释里**，评委试原型时才知道怎么进得去。

### 1.4 交互清单

| # | 元素 | 触发 | 动作 | 结果 |
|---|---|---|---|---|
| 1 | 页面 | 载入 | 若 `LoginUser` 非空 → 设置文本回填账号 | 支持「记住账号」 |
| 2 | `btn_登录` | 单击 | 条件用例：账号为空 → 显示错误、输入框置错误状态、停止 | 表单不提交 |
| 3 | `btn_登录` | 单击 | 条件用例：密码为空 → 同上 | 表单不提交 |
| 4 | `btn_登录` | 单击 | 条件用例：验证码为空 → 同上 | 表单不提交 |
| 5 | `btn_登录` | 单击 | 条件用例：账号=2021001 且 密码=123456 → 设 `LoginUser`、`Role=STUDENT`、打开 P2 | 学生进入 |
| 6 | `btn_登录` | 单击 | 条件用例：账号=T001 且 密码=123456 → 设变量、打开 P6 | 教师进入 |
| 7 | `btn_登录` | 单击 | 否则（Other）→ 显示 `dp_登录错误`，文案「账号或密码错误，请重新输入」 | 停留本页 |
| 8 | `ipt_密码` | 按键松开 | 条件：按键 == Enter → 触发 `btn_登录` 单击 | 回车提交 |
| 9 | `img_验证码` | 单击 | 设置图片为另一张占位图 + 清空 `ipt_验证码` | 模拟刷新 |
| 10 | `lnk_忘记密码` | 单击 | 显示 `dp_忘记密码提示`（淡入 200ms） | 弹提示 |
| 11 | `dp_忘记密码提示` 的「知道了」 | 单击 | 隐藏该面板 | 关闭弹窗 |
| 12 | 输入框 | 获得焦点 | 隐藏自身下方的错误提示、恢复边框 | 错误态复位 |

### 1.5 状态设计

| 状态 | 表现 |
|---|---|
| 初始 | 表单为空（或回填记住的账号），所有错误提示隐藏 |
| 校验失败 | 对应输入框下方红字 + 输入框红边框；不清空已填内容 |
| 认证失败 | 卡片内表单上方出现红底提示条；密码框清空，账号保留 |
| 加载中（可选） | 登录按钮文字变「登录中…」并置灰，1s 后恢复 |
| 成功 | 直接跳转，不做成功提示（登录成功提示会拖慢体验） |

### 1.6 Axure 制作要点

1. **先做背景再用中轴对称**：卡片 `x = (1440-480)/2 = 480`，让整页左右完全对称。
2. 「错误提示」用**动态面板**而不是普通文本：以后要加「加载中 / 网络错误」多个文案时，只需增加面板状态。
3. 密码框的密文效果在 Axure 里是 `文本框 → 属性 → 类型：密码`，**不是**把文字手动换成 `****`。
4. 条件用例顺序务必是：教材空值校验 → 学生匹配 → 教师匹配 → Other。**Other 用例放最后**。
5. 回车提交需要选中密码框 → `交互 → 按键松开时` → 条件 `按键 == Enter`。
6. 把两个测试账号写进 `页面 → 说明` 面板，并勾选发布时的「包含页面注释」。

| # | 元素 | 触发 | 动作 | 结果 |

### 2.5 状态设计

| 状态 | 表现 |
|---|---|
| 有数据 | 卡片内显示统计条 + 表格 + 分页 |
| 空 | 隐藏统计条与表格，显示 `dp_空状态`：图标 + 「暂无成绩数据」+ 「试试切换学期或清空筛选条件」 |
| 筛选无结果 | 同空状态，但辅助文案改为「没有找到符合「数据结构」的成绩，请更换关键字」 |
| 加载中 | 表格区覆盖半透明遮罩 + 居中转圈（原型可用静态圆形代替，200ms 后消失） |

### 2.6 Axure 制作要点

1. **中继器是本页的技术核心**：先给 3 条数据跑通「列显示 → 筛选 → 空态」，再补到 8 条。
2. 统计条里的数字可以**直接写死示例值**，然后在元件注释里写明「由后端聚合计算」——不要为了 `sum()` 表达式卡住整个进度。
3. 「申请查分」按钮建议做成 `112×28` 的**文字按钮**（主色、无底色），比实心按钮更符合表格内操作的视觉惯例。
4. 着色：把总评单元格设为中继器里的独立文本，加两个条件用例（`[[Item.总评]] < 60` / `< 80`）设置文字颜色。
5. 页码 `‹ 1 2 ›` 可以用两个按钮 + 一个「当前页」文本实现，**不需要真做多页**，原型阶段演示点击翻页效果即可。
6. 表格宽度合计 1052 要**和你的列宽精确一致**，否则中继器错行。

### 4.6 Axure 制作要点

1. **中继器 + 表格输入框**：中继器里放文本框是可行的，但中继器的「列」和「输入框」要按 §4.2 的列宽精确摆放，并设为水平排列 + 换行。
2. 自动算分的核心是 `OnLostFocus`（**不是**「文字改变时」，否则每敲一个字符都算一次，体验很差）。
3. 如果中继器里做自动计算太复杂，**降级方案**：用静态表格（10 行手工摆放）实现，同样完成 FR-P4-02；在元件注释中说明即可。**这是允许的，不要死磕。**
4. 输入框限制数字：`属性 → 类型：数字`，并设置最小 0 / 最大 100。
5. 「已录入 x / 共 y 人」的进度用文本即可，`[[已录入数]]/[[总数]]`。
6. 底部保存条设为「固定到浏览器底部」，长名单滚动时按钮始终可见——这是很能体现细节感的一处。

| 新总评 | `lbl_新总评` | 只读 | — | 自动计算 | — |
| 修改原因 | `ipt_修改原因` | 多行文本 | ✅ | 5~100 字 | 请填写修改原因（5~100 字） |

**业务约束**

1. 原成绩三项**只读**，只允许改新成绩。
2. 新成绩与原成绩完全相同时，不允许保存：「新成绩与原成绩相同，无需修改」。
3. 保存必须二次确认，确认后才写入记录。
4. 若该成绩状态为 `APPEALING`（查分中），**整个对照卡片只读**并显示锁定提示条。

### 5.5 状态设计

| 状态 | 表现 |
|---|---|
| 未查询 | 显示 `dp_未查询`：「请输入学号、姓名或选择班级课程开始查询」 |
| 查询无结果 | 同区域显示「未查询到『2021999』的成绩记录」+「请检查学号是否正确」 |
| 查询成功 | 显示对照卡片，原成绩灰底只读，新成绩预填原值（便于微调） |
| 查分中（锁定） | 顶部橙色提示条 + 卡片整体 60% 透明 + 输入框禁用 + 保存按钮禁用 |
| 校验失败 | 对应输入框下方红字，保存不执行 |
| 二次确认 | 居中弹窗：「确认修改成绩？」+「平时 85→90，期末 92→88，总评 89→90」+「修改后原成绩将保留在修改记录中」+ 取消/确定 |
| 保存成功 | 顶部绿色提示条「修改成功，已生成修改记录」+ 表格首行新增记录 |
| 无修改记录 | 记录卡片显示「暂无修改记录」 |

### 5.6 Axure 制作要点

1. 「原成绩 vs 新成绩」用**两组并列的文本 + 文本框**，左列只读灰底（用矩形 + 文本实现，不要用禁用文本框，视觉更干净）。
2. 二次确认弹窗里要**动态显示改动前后值**：用 `设置文本` + 文本拼接 `[[原值]] + "→" + [[新值]]`。
3. 修改记录用中继器「添加行」实现，**时间字段用 `[[Now.getFullYear()]]…` 表达式**，注意月份 +1。
4. 保存成功后除了加行，还要**同步更新卡片里的原成绩**（把新值写回原成绩区），否则用户连续改两次会看到过期的原值。
5. 「查分中锁定」是一个**业务流程约束**的体现，务必做出来——这是 P5 与普通「改分页面」的区别所在。

### 6.6 Axure 制作要点

1. **标签页首选「动态面板 + 两个状态」**，状态名就叫 `待受理` / `已受理`，`设置面板状态` 时按名称切换，不容易错。
2. 两个标签的选中态用**「选中」交互样式**实现（一个组内互斥），不要手工控制颜色，否则切换几次就乱了。
3. 「跨中继器搬行」是本站最难的一处，拆成两步做：
   - 第一步：`tb_待受理 → 删除行 → 当前行（[[This.index]]）`
   - 第二步：`tb_已受理 → 添加行 → 用变量 CurrentAppeal 等填充`
   先跑通「删除」，再补「添加」。
4. 弹窗内填充详情用 `设置文本 + 局部变量`：局部变量从**被点击行的中继器数据**取，别去读行内文本（容易取到错行）。
5. 遮罩层和弹窗务必**同层级相邻**，用一次交互同时显示 / 隐藏；遮罩要比弹窗早一层但晚于其他内容。
6. 若时间不够，「驳回」可以简化：用与受理相同的弹窗，只是按钮文案和状态值不同。
